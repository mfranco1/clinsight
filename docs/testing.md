# Testing and verification

Choose checks based on the changed contract. The complete CI sequence is in `.github/workflows/ci.yml`.

For documentation changes, run `npm run docs:check` and `npm run format:check`. Application code or build configuration changes must at least type-check and build; `npm run lint` includes typecheck.

| Change                                               | Useful checks                                                                                                                                                                                                                                                                   |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Domain rule, migration, parsing, or pure utility     | Focused Vitest file, then `npm test` when shared contracts are affected                                                                                                                                                                                                         |
| React view, hook, or interaction                     | Focused component/hook tests; relevant Playwright workflow for user-visible behavior                                                                                                                                                                                            |
| Loading, lazy feature, or navigation feedback        | Verify accessible polite status text, reduced-motion skeleton styling, first-load fallback, failed import retry, warm remount reuse, and view/identity keyed scroll restoration                                                                                                 |
| Rich-content parsing or presentation                 | Verify Markdown/GFM and math syntax, safe HTML filtering, link schemes, source preservation, citations, responsive wide-content behavior, and the synthetic large-note Playwright budget                                                                                        |
| Text editor or document mode                         | Verify exact no-op source preservation, unsupported-content fallback, save/cancel and external-update behavior, keyboard shortcuts/IME guards, undo/redo, safe HTML paste transformations, table/task-list serialization, identity changes, and desktop/mobile browser journeys |
| Persistence, attachment, or import/export            | Persistence/attachment unit tests and relevant browser reload/import/export path                                                                                                                                                                                                |
| AI task or transport                                 | AI contract, parsing, and transport tests; do not claim a successful local test proves provider availability                                                                                                                                                                    |
| Type, style, configuration, or documentation checker | `npm run lint`, focused tests/check, and `npm run format:check` as applicable                                                                                                                                                                                                   |
| Broad change or release candidate                    | `npm run lint`, `npm run format:check`, `npm test`, `npm run build`, `npm run test:e2e`                                                                                                                                                                                         |

Tests live under `tests/`; Playwright journeys are in `tests/e2e/`. Fixtures in `tests/fixtures/` and `tests/patient-cases.ts` are synthetic/de-identified. Keep those constraints for new examples.

All test paths are offline by default. Vitest blocks and records unexpected `fetch` and `XMLHttpRequest` use, and fails the test even if application code catches the resulting error. Playwright uses an isolated `test` build that never loads local environment credentials; the Gemini transport rejects provider calls in test mode. Its shared fixture permits only the local app origin, stubs the external font stylesheet, blocks service workers and WebSockets, and fails on any other external request. Do not add credentials or exceptions for live provider traffic. Test AI behavior through synthetic gateway/task responses and transport-boundary mocks.

CI checks type/lint, Prettier, documentation, unit tests, production build, then installs Chromium and runs desktop and mobile browser projects on Linux. `npm run lint` already includes typecheck. E2E execution itself performs a fresh production build through Playwright's web server.

## Screenshot baselines

Screenshot baselines include the host platform in their filenames. Keep and review a baseline for every supported platform and project. For an intentional visual change, generate baselines on each represented platform with `npm run test:e2e -- --update-snapshots`, inspect every changed image, and commit the reviewed files. Linux baselines must be generated and reviewed on Linux; a macOS update does not create them. Normal CI runs do not update snapshots.

Failed CI browser runs retain `test-results/` screenshots, traces, and comparison output as a seven-day GitHub Actions artifact, named with the run ID and attempt number. Download it from the run's Summary page while signed in. When the error reports a missing baseline, the captured `dashboard-shell-actual.png` for each project can supply that platform's baseline after visual review and confirmation that the run's application, tests, and lockfile match the intended revision. Place the reviewed images in `tests/e2e/smoke.spec.ts-snapshots/` using the expected filenames from the log, then verify on the same platform without snapshot updates. A screenshot captured for a visual mismatch requires investigation before it can replace an existing baseline.

## Secret scanning

The CI secret scan fetches full repository history and runs Gitleaks with its findings redacted; comments, summaries, and uploaded finding artifacts are disabled. For a local scan of all available refs and reflog commits, install Gitleaks and run `gitleaks git --log-opts="--all --reflog --full-history" --redact=100`. A local scan cannot establish coverage of refs or prior copies absent from the clone. Organization-owned repositories must configure the optional `GITLEAKS_LICENSE` GitHub secret required by the Gitleaks Action.

Record only commands actually run and their result. A build does not verify live Gemini access, deployment, production credentials, backup recovery, or clinical correctness. For visual changes, inspect the affected desktop and mobile paths; use snapshots only where they materially guard a stable layout.
